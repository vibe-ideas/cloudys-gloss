# 中文译文的中西文混排

2026-10-18。科技圈阅读中，模型经常返回 `使用React构建API，支持3种模式。`。展示前统一整理为 `使用 React 构建 API，支持 3 种模式。`，避免中文与西文挤在一起。

## 产品规则

- 汉字与拉丁字母、阿拉伯数字相邻时补一个普通空格；支持带重音的西文和扩展汉字。
- 保留 `Node.js`、`GPT-4o`、`C++`、`C#`、小数、版本号与百分号内部形式。`20%的延迟` 整理成 `20% 的延迟`。
- 不压缩原有空白，不合并换行、段落和缩进，不强行替换中文或英文标点。
- 反引号代码、波浪线代码块、URL、邮箱和识别到的绝对／显式相对路径内部逐字保留。无分隔符的中文 URL／路径后缀有歧义时优先保留地址。
- 英文输入框翻译、词卡英文例句、词头、词性、音标、原网页及导入词库正文保持不变。
- 超长字段补空格会越过现有消息或 Zod 长度限制时保留完整原值，不截断内容。

[W3C 中文排版需求](https://www.w3.org/TR/clreq/)讨论中西文混排间距。这里选择普通空格，是为网页文本、PDF 绘制和复制文本提供一致体验的产品约定；不将其表述成所有中文写作场景必须遵守的国标。

## 实现边界

[公共格式函数](../../src/core/chinese-spacing.ts)只在后台服务交付中文译文时运行，覆盖流式段落、最终结果和旧缓存。缓存继续保存模型原始输出，不改缓存版本、不清空缓存、不增加推理或存储请求。AI 词卡只整理中文释义、语境解释与中文例句。

采用幂等处理；首段仍在抵达时立即推送，不等待整批。没有 DOM 遍历、额外依赖或持续动画。当前不自动润色句式、改变措辞或猜测标点含义，避免排版处理改变技术语义。
