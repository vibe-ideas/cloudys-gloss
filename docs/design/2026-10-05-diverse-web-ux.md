# 多样化网页体验回归

本轮只处理阅读与交互体验，不调整模型、提示词或翻译质量评分。用三个体验设计代理分别检查阅读层级、复杂布局与悬浮交互，按“发现问题 → 建立固定用例 → 修复 → 双浏览器复测 → 截图复核”执行。

## 真实网页

环境为 macOS / M4 Pro、Firefox Developer Edition 158.0，使用当前本机 mlx-serve 与 Qwen3 1.7B 4bit 配置。保留已有缓存，包含新请求；每站浏览一轮，发现问题的部分修复后复测。本表记录实际检查区域，不表示逐屏覆盖了整个站点，也不提供延迟、TPS 或质量统计。

| 页面 | 检查范围 | 观察与处理 |
| --- | --- | --- |
| [Apple iPhone 18 Pro](https://www.apple.com/iphone-18-pro/) | 首屏购买区、相机轮播附近、深色大标题 | Buy 不再附加低对比度译文；大号视觉标题的中文改为清晰的白色，所见内容无叠压；导航保持原样 |
| [MDN Intersection Observer API](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API) | 概述、列表、创建观察器、代码示例与参数说明 | 正文和标题逐段显示，左右侧栏保持原样；代码块不翻译，代码前后文字没有覆盖 |
| [Wikipedia Translation](https://en.wikipedia.org/wiki/Translation) | 首段、目录、浮动图片、图注、词源、公告关闭 | 发现搜索区域的隐藏文字变为孤立译文，已过滤；重载后搜索栏正常，关闭当前公告无残留译文；正文绕图和图注无叠压。捐赠公告再次加载时已换成另一条公告，原捐赠隐藏链接场景另由固定用例覆盖 |
| [Hacker News](https://news.ycombinator.com/) | 首屏密集表格列表与顶部操作区 | 发现旧式表格导航被作为正文翻译，补充短链接工具条及同一行登录入口识别；最终复测导航保持单行，标题和元信息的双语行未重叠。元信息仍可翻译，因此列表会比原页更长 |

## 修复与稳定用例

夹具是原创页面结构与固定模型响应，不是线上站点复制件。故意使用长中文，覆盖 1100px 桌面和 390px 窄屏，并在产品页验证缩窄后再恢复桌面宽度。

| 体验问题 | 修复 | 回归入口 |
| --- | --- | --- |
| 固定高度卡片裁字、网格卡片覆盖下一行 | 新增译文溢出时允许正常流容器增长，普通自动排列网格按内容撑开 | `tests/e2e/layout-design.spec.ts`、`diverse-layout.spec.ts` |
| 关闭翻译误还原网页的新样式 | 记录宿主在会话中的更新，跟踪相关祖先尺寸，恢复时保留最新高度和颜色 | `layout-design.spec.ts` 的“网页在翻译期间更新卡片高度后…” |
| 巨型展示标题下面出现小号灰字 | 插入前识别大号主要子元素的字体和颜色，中文标题最高 28px | `layout-design.spec.ts` |
| 控件、多链接导航与隐藏辅助文字产生孤立译文 | 排除操作控件、搜索区和工具条；仅对附近语义块检查样式隐藏和读屏裁剪 | `tests/e2e/auxiliary.spec.ts`、`tests/unit/blocks.test.ts` |
| 内部滚动面板被撑高或末段一直等待 | 保留滚动壳尺寸，共享容器 IO 提前处理附近段落，并以外层可见性门控 | `diverse-layout.spec.ts`、`tests/unit/translator.test.ts` |
| 小窗口词卡遮选区、窗口重排后离开原词 | 依据实时 Range 避让，空间不足时限制高度并在卡内滚动 | `tests/e2e/interaction-design.spec.ts` |
| 网页拦截事件导致菜单无法关闭、Esc 抢焦点 | 捕获阶段处理外部点击；仅在菜单内部有焦点时将其还给入口 | `interaction-design.spec.ts`、`extension.spec.ts` |

原有 2000 段大页面、渐进返回、缓存、取消任务、SPA 增量处理、主题和减少动态效果测试继续执行。首次提取保持分片；只测量附近待翻译块及已跟踪的相关祖先；布局更新由共享 ResizeObserver 与帧回调合并，不重复扫描全页。

## 验证结果

- `pnpm check`：ESLint、TypeScript、189 项单测通过。
- Chrome 与 Firefox 生产构建通过；42 项 E2E 均已验证通过。最终全量执行先通过 41 项，另 1 项仅因 Firefox 对相同 36.8px 高度的浮点舍入差异失败（约 0.000015px）；高度断言改为小数点后两位比较后，该场景在两浏览器重跑 2/2 通过，DOM 和请求断言保持不变。
- 真实 Firefox Developer Edition 已重载最终构建，Wikipedia 隐藏搜索文字与 Hacker News 单行导航已现场复测。

## 设计复核与边界

设计代理先后指出并推动修正了固定网格裁切、折叠摘要的孤立译文、滚动壳被撑高、内部预取停滞、小窗口词卡避让、Esc 焦点回归和宿主样式恢复问题。最终受控截图中，资讯网格、展开长文、图注引用和固定/绝对定位阅读面板未见新增文字重叠；自动化同时检查几何边界和功能，不单靠目测。

非滚动的绝对或固定定位覆盖层仍采取保守跳过策略，因为增加高度无法可靠移动其相邻覆盖层；可以主动划词。命名网格、显式跨行跨列和网站原本存在的重叠不会被全局改写。超长选区占满整个视口时，词卡优先保证可操作，可能覆盖部分选区。上述边界不能被描述为“全网绝对无问题”。

截图、诊断 JSON 和 Playwright 报告分别由测试输出至 `test-results/`、`artifacts/`、`playwright-report/`，不提交原始机器资料。后续发现站点问题继续在 `tests/` 增加最小结构回归，不为某次模型译文写死页面修补。
