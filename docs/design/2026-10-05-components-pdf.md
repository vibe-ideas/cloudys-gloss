# 页眉、常见组件与 PDF 体验修复

本轮针对用户反馈的页眉、面包屑漏译，以及 PDF 阅读支持；不评价模型翻译准确率。上一版为避免重叠，将导航与操作区域整体排除，这使页面入口无法双语阅读。本轮拆分语义标签，并按可用空间选择展示方式。

## 组件展示约定

| 场景 | 当前行为 | 保留的原操作 |
| --- | --- | --- |
| 正常流中的页眉、导航、面包屑 | 每个标签下显示紧凑译文，允许局部换行 | 链接地址、原文和页面阅读顺序 |
| 按钮、标签页、菜单项、表格操作 | 标签独立翻译，不把整条工具栏拼成一段 | 点击、禁用状态、Tab 焦点与切换行为 |
| 折叠摘要、按 CSS 显隐的菜单和面板 | 展开后局部发现或重新调度 | 原有展开状态，不反复扫描整个页面 |
| 表单 label、legend、复选框可见标签 | 静态标签双语，译文作为辅助描述 | 输入值、提交数据和可访问名称 |
| 固定或绝对定位覆盖层、受限吸顶控件 | 不强行增高；译文完成后出现点状下划线 | 悬停、原有键盘焦点或触屏长按查看；普通点击仍执行原操作 |
| 模态对话框中的受限内容 | 提示进入顶层显示，避免被 backdrop 遮住 | 不抢焦点，不替代宿主对话框 |

受限区域全页共享一个提示层。长译文限制在屏幕内并可滚动；仅悬停时，鼠标离开会收起。键盘焦点仍在原控件时，鼠标移出不会关闭提示，窗口缩放只重定位，保留阅读位置。Esc、焦点离开、页面滚动和关闭翻译会收起；译文与原文相同时不留下重复行或可用标记。关闭翻译会清除自己的节点、样式、描述 ID 和监听，同时保留宿主页在翻译期间追加的描述与状态。

## PDF 阅读方式

PDF 使用独立扩展阅读器，支持本地文件和 HTTP(S) 链接。打开只解析原文；点击「开启双语」后通过原有 background 队列与缓存翻译当前页。原始页面与可复制的原文、中文逐段对照，窄屏上下排列。切页、暂停、关闭和取消均停止旧任务，迟到结果不会覆盖新文件。

解析使用本地 Worker，PDF.js、字体、字符映射和图像解码器只由阅读器加载。下载上限 40 MB、单个活动画布上限 300 万像素，每页最多提取 200 段或 100,000 字符。画布像素不是整个解析进程的内存上限。完整操作与限制见 [PDF 使用指南](../guides/pdf.md)。

## 专家审核发现并修复的问题

体验设计、UX 交互和技术三个代理分别审阅实现、测试契约与截图，主代理整合并运行跨浏览器回归。

| 问题 | 修复与对应回归 |
| --- | --- |
| 整片导航被排除，控件失败态可能嵌入第二个按钮 | 逐标签提取；控件内只显示非交互译文；`component-design.spec.ts` |
| 菜单仅切换 hidden/class 后不翻译 | 局部显隐监听；主题切换不重新遍历 2000 段；`translator.test.ts` |
| 密集标签占用正文请求、裸链接组反复分类 | 正文优先、短标签最多 8 项一批；扫描上下文缓存与变更失效；`performance.spec.ts`、`blocks.test.ts` |
| Firefox 可见性回调先后到达，导航偶发抢在正文前 | 按观察时间合并浏览器已计算的交集，正文优先级不依赖回调顺序；`translator.test.ts` |
| 大容器的一次文字读取突破外层扫描预算 | 可暂停的语义读取；首屏子块可先发现，挂起期间宿主改字会重启读取；`translator.test.ts` |
| 首次扫描暂停时网页删除当前节点，后续兄弟漏译 | 保存各层安全后继，从存活节点继续；`blocks.test.ts`、`translator.test.ts` |
| 已完成段落内部文字仅由 CSS 显现后仍保留旧译文 | 标记相关块，在合并读取阶段比较实际可见文字，再局部重译；`translator.test.ts` |
| 普通 HTTP 网页无 randomUUID 导致全文和词卡失败 | getRandomValues 回退；真实非安全上下文验证；`http-context.spec.ts` |
| 长提示超屏、离开后残留、Esc 后新片段使提示重开 | 边缘避让、可滚动、明确关闭状态；`component-design.spec.ts`、`translator.test.ts` |
| Linux CI 中窄屏长提示在聚焦后提前隐藏 | 确定性复现并修复焦点后缩放、鼠标移出两条同症状路径；缩放合并到一帧重定位、离开计时再次检查焦点，关闭取消待定位帧；`component-hints.test.ts`、`component-design.spec.ts` |
| 长提示缩窗后受旧 left 影响，定位后再次变宽而溢出留白 | `width:max-content` 配合最大宽度，使宽度独立于位置；360px 双端断言边界和滚动位置，并留存截图与几何记录 |
| 模态遮罩覆盖提示、关闭后残留描述 ID | 顶层显示并检查真实命中；只清理自己的描述 token |
| PDF 离屏后原图丢失、页码 blur 覆盖输入 | 保留当前页画布生命周期；明确提交跳页；`pdf.spec.ts` |
| PDF 解析退回主线程、取消后等待挂起 | 显式本地 Worker、销毁和取消竞速；`pdf.spec.ts` |
| PDF 窄屏原图短暂纵向拉长 | 保留画布固有比例，浏览器断言显示宽高比 |

可执行场景统一维护在 `tests/`，不复制到文档形成另一份测试规范。截图与机器日志在被忽略的 `artifacts/`；性能口径见 [组件与 PDF 性能报告](../performance/2026-10-05-components-pdf.md)。

## 验证记录

- 最终补丁的 `pnpm check`：ESLint、TypeScript、229 个 Vitest 用例通过。
- 主体功能构建 `226222f` 的本机 Chrome / Firefox 完整 E2E 60 项通过，包含 PDF、普通 HTTP、组件显隐、原点击行为、窄屏和关闭恢复。
- 后续长提示修复的双浏览器组件 E2E 6 项通过，UX 代理另行目检两端 360px 截图。提示框均位于 x=28、y=12、宽 320、高 532 的范围内，底部来源控件与焦点轮廓可见，缩窗后滚动位置保留。
- 2000 张卡片性能独立重复 6 次全部通过；首段显示中位数 Chrome 94ms、Firefox 115ms，固定模型响应下最大帧间隔约 17–19ms。方法、对照、测试工具干扰的排查及限制详见性能报告，不能作为 MLX 推理基准。
- 体验、UX 与技术代理发现的上述功能问题已修复并复核。大型网格同步几何检查和特殊大单块同步核对仍列为性能边界，不宣称所有网站完全无问题。

首次 [Linux CI](https://github.com/vibe-ideas/cloudys-gloss/actions/runs/37234915936) 为 59/60：长提示已有内容却提前隐藏。原日志没有记录事件顺序；随后在旧源码上稳定复现了聚焦后缩放、聚焦后鼠标移出两条同症状路径，并修复及加入回归。进一步缩窗检查还发现宽度与旧位置相互影响的问题，同样修复并保留断言，没有增加重试或放宽阈值。最终提交的完整 CI 与打包结果见 [GitHub 工作流](https://github.com/vibe-ideas/cloudys-gloss/actions/workflows/ci-release.yml)。

## 明确边界

- 支持的是具有可见文字的组件标签；原生 select/option、placeholder、仅图标的 aria-label 不在本轮翻译范围。输入框、可编辑区域和用户输入值不发送给模型。
- 站点自身的 Shadow DOM、iframe、虚拟化编辑器仍未遍历；非英文/拉丁字符为主的源文识别策略未扩展。
- 点状下划线表示可查看译文，受限固定区域不会永久插入第二行。已有重叠或显式网格布局也不会被强行重排。
- PDF 暂无 OCR、密码输入、双语导出和原生批注/表单交互；多栏、公式和复杂表格的文本提取顺序可能与原稿不同。
- 自动化使用固定译文验证布局与交互，不能证明模型语义准确，也不能证明所有网站都不存在兼容问题。
