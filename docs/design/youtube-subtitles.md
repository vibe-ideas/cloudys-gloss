# YouTube 字幕读取、调度与显示

## 实现边界

视频功能使用独立 WXT content entrypoint，仅在 YouTube 域名加载，支持 `/watch` 与 `/embed` 路径。其余网页不加载视频调度器、解析器或额外观察器。模型请求复用 `translateStream → background → TranslationService`，不增加权限，不把模型地址、API Key 或网页 Cookie 交给页面脚本。

用户开启双语后，用 WXT `injectScript` 加载约 90 KB 的页面桥接脚本（含字幕校验器，仅开启时加载）。它通过 PerformanceObserver 查找播放器实际使用的 `/api/timedtext` 地址；不存在时尝试播放器暴露的字幕轨道。地址必须属于 YouTube HTTPS、精确匹配当前视频，并拒绝带 `tlang` 的自动翻译轨道。请求在页面同源环境读取当前可访问的字幕，不构造访问令牌、不绕过登录或访问限制。开启期间临时包装 fetch / XHR，只复用当前视频字幕响应；返回原 Promise / Response，不改请求参数，也没有整页轮询。关闭时恢复原方法，若其他扩展已替换方法则不覆盖。

完整字幕读取失败时，只观察当前播放器内的 `.ytp-caption-segment`。滚动字幕合并、去重，并使用 180 ms 防抖与 650 ms 最长等待。该降级模式没有未来时间轴，因此不能承诺预翻译。播放器保留 CC 原始状态；模型请求取消与读取取消分别由 runtime port / AbortController 处理。

## 同步与性能预算

- JSON3 通过 Zod 校验；兼容 srv3 / legacy XML。输入最多 4 MiB、30,000 个事件；时间为非负有限数，单条持续时间最多 30 秒。
- 自动字幕追加片段合并。相邻未完句进一步合并，但以 10 秒、220 字符、句末标点和停顿为边界。原文始终作为文本渲染，不插入字幕提供的 HTML。
- 时间轴通过二分查找定位；播放使用媒体事件，不运行每帧定时循环。字幕未变化时跳过 Preact 更新。
- 当前句优先单独返回；随后串行填充未来 120 秒，倍速按实际观看时间放大，最多检查 64 个合并片段。预取每批最多 8 条、2,400 字符，沿用后台全局并发限制和低优先级队列。
- 缓冲较充足时，至少积攒 4 个未翻译片段再补一批，避免每经过一句就产生一次小请求；不足 30 秒时允许小批补充。
- 会话缓存最多 500 条；IndexedDB 仍按现有模型配置与原文缓存。配置改变清理会话缓存。失败后暂停后台预取 30 秒，用户可以直接重试当前句。
- 取消后丢弃未确认流式缓存，旧会话结果不能写回新视频。广告、后台标签页、关闭、导航和扩展重载都有清理路径。
- Shadow DOM 双语层位于播放器内部，随全屏显示，不参与页面排版。仅有双语原文可显示时隐藏原生字幕；关闭移除覆盖样式，不改写网站原文。
- 网页全文翻译跳过原生字幕容器，避免与视频模块重复翻译。

## 调研依据与限制

[沉浸式翻译使用说明](https://immersivetranslate.com/en/docs/usage/)提供播放器双语字幕入口；[更新记录](https://immersivetranslate.com/docs/CHANGELOG/)提到自动英文字幕的智能分句。本实现同样提供显式开关和有界合句，尚未覆盖其全部站点与字幕编辑能力。

[WXT 注入脚本 API](https://wxt.dev/api/reference/wxt/utils/inject-script/functions/injectscript)用于跨浏览器页面桥接。[字幕读取实现者的实测](https://prepublish.ai/guides/youtube-timedtext-empty-response)记录过 HTTP 200 但正文为空的情形，因此不能把状态码当作成功。这些 YouTube 播放器接口并非公开稳定契约；本实现保留实时 CC 降级和读取重试，需要用真实视频持续验证。

本功能不会下载视频或音频。影片不存在可读取字幕、播放器结构变更、页面脚本注入被阻止、账号限制或网络错误，都可能使提前翻译不可用。模型生成速度不足时，扩大缓冲不能保证冷启动或长距离跳转后立即追上。


## 右侧历史字幕

`SubtitleHistory` 保存按时间排序的本次观看记录，按时间和原文分别建立索引。调度器每次绘制只更新当前条目，流式结果与校验撤回按原文更新已存在的历史条目；未观看的预取结果不会生成观看记录。重复播放同一时间的句子不会新增重复条目。记录最多 1,000 条，超限释放较早的非当前记录；跳回早期位置时仍保留当前句。

`SubtitleSidebar` 采用独立 Shadow DOM，复用已有模型调度，不引入浏览器专属 sidebar API 或权限。普通播放页停靠现有右侧推荐列；影院、全屏和宽幅嵌入播放器通过带扩展标记的 CSS 为右栏预留最多 320 px，视频、字幕与控制栏同步避让。关闭后移除标记和布局变量，恢复原样。窄窗口将侧栏放到播放器下方。

通过播放器和右侧列的 ResizeObserver 合并布局更新，每帧最多一次；主题只观察根元素的 dark 属性。记录修订号未变化时不重新渲染。列表每次只渲染 40 条，关闭面板卸载列表，翻页可访问其余记录。自动跟随只滚动侧栏内部；手动滚轮、触摸、滚动条和键盘翻阅暂停跟随，新的译文不能抢走阅读位置。点击时间戳使用原始小数时间跳转，不主动改变播放状态。

同一视频关闭/重新开启字幕可保留会话记录；SPA 换视频、字幕轨道改变、模型配置改变时清空，刷新页面后不持久化。所有观察器、事件监听、布局回调及 DOM 在内容脚本失效或离开视频时销毁。


## 读取恢复与实时 CC 调度

轨道加载器每个会话最多 8 个候选地址、2 个并发，每候选最多 3 次尝试，退避 500 / 1,500 ms；每次请求 10 秒超时、最多 4 MiB。空响应和无法解析的正文都不算成功。失败的最近地址会触发 metadata 回退；metadata 最多查询 3 次。首个有效同轨道响应可以发布，较晚失败不能覆盖它。身份由 lang / kind / name / vssId 组成，签名和格式变化不算切轨；真实切轨立即清除旧显示并回到新 CC。页面桥接不记录带签名的地址。

后台标签页暂停请求；切回同视频复用先前验证过的轨道，同时恢复观察，以便接收语言或人工/自动字幕的变化。自动恢复预算耗尽后，需要重新开关双语以开始新会话。持续拒绝或失效链接仍可能只能使用实时 CC，不绕过访问限制。

实时 CC 正常更新不取消普通在途请求，旧句结果按原文精确补入历史，不能显示到不同的新句。只保留最近 4 个待补快照，12 秒过期；当前句优先，每批最多 3 条 / 2,400 字符。已缓存或已报错的文本不占待补名额。过载时丢弃老的待补项，保证队列有界，不承诺全部历史自动补齐。旧句的失败不自动重试；当前句仍遵守已有两次重试规则。429 冷却在当前调度器内共享，换句不能绕过。

跳转、关闭、导航仍立即取消。实时历史行的手动重试要等跳转后的相同 CC 原文重现才消费意图，避免对旧 DOM 请求。ASR 回看若改写原文，精确匹配可能无法触发原记录重试，不做模糊匹配。


## 优先复用播放器原始字幕响应

先安装响应观察器，再通过 ready 握手通知内容脚本开启 CC，避免 CC 第一次请求发生在观察器就绪之前。仅匹配当前视频的 GET `/api/timedtext`，拒绝其他视频、音视频流和自动翻译轨道。fetch 返回原始 Promise，读取 Response.clone 的副本；XHR 只读已完成的 text / json 响应。模型调用仍只在 background。

副本最多 2 个并发、10 秒、4 MiB，停止时取消自己的副本和监听，不中断播放器原请求。Response.clone 的慢分支可能缓冲数据，因此按流增量计数并取消超限副本，不使用无界 response.text。[MDN 对 clone 的说明](https://developer.mozilla.org/en-US/docs/Web/API/Response/clone)。扩展自己的重试调用未包装的 fetch，避免递归。捕获到空或无效正文才回退下载；无法截获的历史请求仍走已有 metadata / PerformanceObserver 恢复路径。

响应在请求开始时绑定字幕轨道身份。旧语言的迟到响应和对应 ResourceTiming 通知均不能把新语言切回去。直接捕获有效正文后不再额外请求同份字幕。

侧栏直接展示是否获得完整轨道，以及从当前播放位置开始连续确认的中文缓冲秒数（最多显示 120 秒，倍速按实际观看时间计算）。流式未校验内容、跳过缺译空洞后的译文不计为准备完成。实时模式提供“重新读取完整字幕”，用户点击后重启读取会话并切换 CC 关闭/开启以请求原生字幕；最终 CC 开关状态仍按原有规则恢复。该动作不改变视频播放/暂停状态。


WXT 的 MAIN-world `document_start` 入口还提供启动阶段的被动字幕缓存，处理“用户点击双语前 CC 就已下载”的时序。只有 YouTube 页面加载这段小脚本；启动或切入视频后最多观察 30 秒，保留当前视频最近一份正文及公开轨道标签，不保存签名、不自行请求、不调用模型。桥接启动时取走并校验该快照，重复的初始 SPA finish 事件不清空它；切视频和 pagehide 清空。MAIN-world 和隔离世界共用 WXT 声明，没有另写浏览器 manifest。已验证轨道也在同视频关闭/重新开启时复用，显式“重新读取”才丢弃并重新获取。
