# PDF 原版式翻译技术调研与实现决策

日期：2026-10-05。目标是改善阅读体验与数据可核对性，本次不评估模型翻译准确率。用户提供的私人银行截图仅作视觉参考，没有上传、写入夹具或仓库。

## 原型验证

隔离原型在 Chromium 与 Firefox 各运行 10 个场景。对普通彩底、表格、旋转 90°、UserUnit=2 和透明页面，过滤文字后的底图与手工制作的无字参考图逐像素一致。简单过滤在文字裁剪、Type3、图案文字和软蒙版中失败：分别出现 235,275、2,058、8,025、8,031 个不同像素。因此不能把删除 showText 当作通用去字算法。

原型日志和截图保留在忽略目录 `artifacts/pdf-render-research/`，不把第三方源码或私人文件纳入产品。稳定验证维护在 `tests/unit/pdf-render.test.ts` 和 `tests/e2e/pdf/pdf-layout.spec.ts`。

## 实现

1. `src/pdf/layout.ts` 保留页坐标、段落矩形、原文字墨迹矩形、字号与安全性；保守区分多栏和表格单元格。数字、金额、邮箱及 URL 不单独发送模型。仅有文字几何时，两列长句表格与双栏正文可能无法区分，不承诺所有 PDF 的语义结构识别。
2. `src/pdf/render.ts` 绘制原稿，再生成可验证的去字背景。右页先完整复制原稿，只有已得到译文的区域才从背景回填。原稿与背景均使用白色纸面进行合成，避免新画布不支持透明通道时出现黑纸，也避免白纸上的白字被当成可读内容。回填先 clear 再复制；彩底和图片不使用统一白色遮罩。检测后绘图形与原文字的遮挡关系，不能安全回填的区域保留原稿。
3. 渲染器检查固定版本的操作参数。裁剪、Type3、蒙版、图案、不可见文字和未知操作结构等使可见性无法确认时保留原稿，不展示或发送提取文字；已识别的后绘图遮挡也贯穿到数据过滤层。仅几何不适合原位排版、且可见性验证通过时使用阅读模式。升级 PDF.js 必须重新验证，不绕过校验。
4. `src/pdf/typeset.ts` 在页坐标中测量文本并换行，最小字号为原来的 80%；超长译文标记“展开”，详情保留完整原文和译文。数值缺失或改变时保留原稿并允许重试；这是数据完整性防线，不是语言质量评分。
5. 桌面双页共用滚动容器和缩放；窄屏用单页切换。暂停保留已完成成果，“显示原文”即时恢复原稿。模型仍走 background、并发队列和 IndexedDB 缓存，缩放不触发新翻译。

## 性能边界与尚未支持

只处理当前页。原稿、译稿和去字背景三个画布总计不超过 600 万物理像素，约 24 MB 原始 RGBA 缓冲；这不等于浏览器进程 RSS，也不包含解析器、字体和模型内存。颜色采样数量与缓存均有界，缩放复用提取结果与译文，连续缩放合并绘制。页面解析仍使用本地 worker。

本次不提供 OCR、双语 PDF 导出、手工移动文本框、原生批注或表单交互。复杂公式、特殊字体和不可靠几何会保留原稿；仅确认可见的文字可用于按段阅读，无法保证任意 PDF 都达到出版级排版。
