# 段落反复重试失败：复现与修复

用户反馈 X 文章的一段英文无论重试多少次都报“模型输出不符合翻译结构要求”。重试按钮确实绕过缓存并发送新请求；在本机模型上，失败原因是批量请求未返回有效结果后，纯文本补译仍只润色英文。温度为 0、重复相同请求时会持续得到相同错误结果。

本次修改只调整失败后的单段补译路径：用简短的中文系统指令，并在用户消息中明确要求翻译、标记原文边界。正常批量提示保持不变，成功段落不重复请求，取消和总超时仍覆盖整个补译过程。可明确对应单段的 `translation` 或单项 `translations` JSON 包装会被提取，再检查正文；多项、未知字段和非中文结果仍拒绝。错误提示区分英文复述、空响应、截断和格式错误。

## 本机实测

2026-10-21，Apple M4 Pro，本机 `127.0.0.1:8080/v1` 的 `Qwen/Qwen3-1.7B-MLX-4bit`，温度 0、并发 1；调用生产 provider，包含流式解析、校验与补译，不使用扩展结果缓存。此次未确认用户浏览器选择的模型，也未固定模型 revision 或服务启动参数，不能视为严格模型横向比较。

| 场景 | 结果 | 请求次数 | 完整耗时 |
| --- | --- | --- | --- |
| 修复前：截图原段落，2 次 | 0/2 返回有效中文，均报错 | 每次 2 次 | 中位数 2.08 秒，到失败为止 |
| 修复后：同段落，5 次 | 5/5 返回中文并通过自动检查 | 每次 2 次 | 中位数 5.00 秒，范围 4.81–5.66 秒 |
| 修复后：既有 18 例，各 1 次 | 18/18 通过自动检查 | 14 例 1 次，4 例 2 次 | 仅作基本回归，不作为速度比较 |

这里修复的是持续失败，并没有宣称生成更快。补译需要完整生成中文，因此修复后的成功耗时比原来快速返回错误更长。5 次相同输入、相同温度的结果相同，只说明这条复现用例可重复通过，不能推出所有网页都不会失败。

### 译文质量限制

本次原段落结果保留了“数量不等于质量/用户成果”和“虚荣指标”的主要观点，但仍留下 `personally`，将智能体译成“代理”，并把“PR 合并数量”简化成“PRs 数量”。这是小模型的质量缺陷，**不能把 5/5 自动通过称为翻译质量满分**。18 例也仅执行自动规则，未完成本轮逐例语义评分。

原文、参考译文和检查规则在 [paragraph-retry-cases.json](../../tests/quality/paragraph-retry-cases.json)。前后结果、代码快照和运行元数据保存在 [实验目录](../../tests/quality/baselines/2026-10-21-paragraph-retry/experiments/)，明确作为未批准的实验记录，不作为已通过质量门槛的基线。

复现命令（输出目录须不存在已有结果）：

```sh
MODEL_BASE_URL=http://127.0.0.1:8080/v1 \
MODEL_NAME=Qwen/Qwen3-1.7B-MLX-4bit \
QUALITY_CORPUS=tests/quality/paragraph-retry-cases.json \
QUALITY_REPEATS=5 \
QUALITY_OUTPUT=artifacts/paragraph-retry-new-run \
pnpm test:quality
```

## 自动化回归

已通过 lint、TypeScript 检查、543 条单元测试，Chrome / Firefox 构建及两浏览器共 18 条网页与 PDF 重试 E2E。浏览器用受控模型响应验证交互；真实 MLX 数据来自上面的 provider 实测，并非用户日常浏览器页面的实测。

- Provider：明确请求中文且完整传递原文；接受单段包装；拒绝复述英文、多项错配、空响应和截断；请求有上限。
- 浏览器：失败段落点击重试，批量响应仍复述英文时转单段补译；只重试当前段，不重翻相邻失败段落，页面不出现提示词包装。
- 既有回归：成功段落保留、请求取消、缓存绕过、SPA 改文后旧结果不回写，以及 PDF 逐段重试。
