# 划词先显示本地释义

## 原因与改动

原先内置词典只有音标；没有手动导入 StarDict 时，中文释义完全等待 AI。结构化输出失败可触发两次语境例句请求和两次生成例句请求，每条路线有自己的超时，排队也不计入超时。

现在增加 57,932 条 ECDICT 通用英汉释义。点击划词按钮后，内置释义、导入词库、音标和 AI 分别请求并独立回填。词典不经过模型队列；导入词库尚未返回也不会阻挡内置释义。普通构建使用已提交的静态分片，不下载数据。

AI 语境和例句仍由原有经过 Zod 校验的流程补充。本次没有放松结构校验，也没有改变生成提示词；不能声称修复了所有模型输出错误。新增统一总等待预算，取设置 Timeout 与 30 秒的较小值，包含排队、启动和各修复路线。超时取消未完成请求，已有词典内容继续可读。重试只发起 AI 请求，不清空词典、音标，也不停止正在播放的读音。

## 数据与开销

- 来源：[ECDICT 固定版本](https://github.com/skywind3000/ECDICT/tree/bc015ed2e24a7abef49fc6dbbb7fe32c1dadaf8b)，保留 MIT 许可。
- 按已有词频和标签筛选，不根据测试词表挑词；构建脚本和输入哈希见 [资产说明](../../public/dictionaries/README.md)。
- 128 个释义分片，单片最大 31,147 字节；含索引和来源文件共 3,437,488 字节。单独 ZIP 压缩为 1,444,852 字节，不是整个插件包大小。
- 最多并发读取两个分片，重复读取合并；分片文本 LRU 预算 256 KiB。这个预算不包含索引、瞬时响应、解析对象和 JS 引擎开销，不等于进程内存。
- 不做全文词典常驻，也不往网页脚本注入词典；没有词条时继续等待 AI，不猜词义。通用释义可能缺少最新科技义项，界面明确区分词典和语境解释。

## 本机浏览器验证

2026-10-20，本机 Apple Silicon Mac，使用项目安装的 Chromium 与 Firefox Developer Edition，加载实际构建的 MV3 / MV2 扩展。输入为公开合成页面中的 `Delightful`。模型为本地模拟服务，前两轮固定延迟 5 秒；第三轮返回非法结构。扩展每个浏览器使用新测试配置，首轮词典分片冷缓存，后两轮复用分片。

| 点击划词按钮到释义可见 | Chromium | Firefox |
| --- | ---: | ---: |
| 首轮冷缓存 | 153.5 ms | 228.9 ms |
| 第二轮热缓存 | 255.8 ms | 212.4 ms |
| 第三轮模型结构错误场景 | 314.1 ms | 187.4 ms |

以上是每种场景一次采样，包含 Playwright 点击和可见性断言的调度开销。热缓存值较高不能推断缓存退步；这些数字不是词典纯查询延迟、稳定 P95 或真实模型生成性能。结果说明在模型仍等待的 5 秒内，词典已经可读。

Chrome / Firefox 共 6 项 E2E 通过，覆盖先出释义、慢模型、非法结构、保留内容重试、原有词卡与导入词库兼容。对应 [稳定浏览器用例](../../tests/e2e/reading/dictionary-first.spec.ts)、[词典单测](../../tests/unit/packaged-definitions.test.ts)、[词卡单测](../../tests/unit/popover.test.ts) 和 [等待预算单测](../../tests/unit/service.test.ts)。
