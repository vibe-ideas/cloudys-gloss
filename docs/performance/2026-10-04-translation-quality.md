# 18 类固定用例：三款 MLX 模型的翻译质量

2026-10-04，本机 M4 Pro。使用插件真实翻译 provider，18 个固定用例 × 2 轮 × 3 个模型，共 **108 次翻译任务**。每款模型的两轮输出完全相同，形成 54 份不同模型/用例的译文。语料版本 1.0.1，温度 0、单并发、关闭 prompt cache；Qwen3 关闭思考。

**在本轮样本和评分尺度下，Qwen3 1.7B 的全文翻译质量最好，17/18 类可接受；另外两款为 14/18。** 这不是广泛准确率：参考译文与评分均由 Codex 编写/逐例审阅，知道模型标签，非独立人工盲评，边界分数有主观性。完整输出和评分理由可公开复核。

## 结果

| 模型（MLX 4-bit） | 自动硬性检查，通过请求数 | 逐例审阅后可接受，用例数 | 有严重错误的用例数 |
| --- | ---: | ---: | ---: |
| 当前 Qwen2.5 3B | 36/36 | **14/18** | 1 |
| Qwen2.5 1.5B | 32/36 | **14/18** | 3 |
| Qwen3 1.7B，关闭思考 | 36/36 | **17/18** | 0 |

每个用例必须两轮都合格才计入“可接受”。自动检查没有能力全面判定语义：3B 的自动检查全部通过，审阅仍发现重要错误。完整评分尺度与门槛见 [质量测试说明](../development/translation-quality.md)。

## 具体差异

### 否定与例外条件，T06

原文：`Do not delete the local backup unless the upload has completed successfully.`

| 模型 | 实际译文 | 审阅 |
| --- | --- | --- |
| 3B | 不要除非上传成功完成才删除本地备份。 | 否定与例外叠加造成歧义，操作条件不能可靠理解，严重错误 |
| 1.5B | 除非上传成功，否则不要删除本地备份。 | 可接受 |
| Qwen3 | 不要删除本地备份，除非上传已经成功完成。 | 可接受 |

### 时间与数字，T05 / T18

原文给出 `12 October 2026`，1.5B 只译成“10月12日”，漏掉截止年份；另一个 `two-hour delay` 被它改成“一小时的延误”。这两类错误由自动检查抓到，两轮均发生，保留为真实测试失败，未为了变绿删除用例。

### API 的作用与执行顺序，T14

原文要求“调用 abort()，然后删除文件”。1.5B 却译为“先调用 AbortController 的 abort() 方法删除……文件”，把取消请求的方法误说成删除文件的方法。API 名字虽然仍能辨认，语义关系已经错误；自动规则通过，逐例审阅判为严重错误。

3B 与 Qwen3 都正确表达了先调用、再删除。

### 自然度与未翻译内容，T02 / T11 / T18

- 3B 将读者 `reader` 译成“读取器”；`surprisingly light` 译成“surprisingly 轻”，留下未翻译词。
- Qwen3 对这些表达更好，但并非全对：反讽延误的场景中，把错过转乘的 `missing our connection` 译成“错过连接”，语气也不够清楚。该用例不合格。
- “重新尝试”作为 Retry 的译法是合理的，不算错误。检查器修正了最初误报，并对三款模型全部重跑。

### 长文是否漏译，T03 / T04

三款模型在本次真实 provider 的“分段批量”和“单块内两段”用例中，都保留了后半篇。这与之前 1.5B 在 TPS 纯文本请求中漏掉第二段并不矛盾：**提示词、返回格式和调用路径不同**。不能把纯文本测速中的漏译直接当作插件管线的必然表现，也不能凭这次没漏译就保证所有长文都完整。

相同原文的两种调用方式已成为固定回归用例。长文仍有局部措辞偏差，例如 Qwen3 把成熟树木译成“树木茂盛”，3B 的“五个年度的几个社区”生硬，完整输出中均有标注。

## 选择结论

把上次 [TPS / 内存](2026-10-04-mlx-models.md) 和本次质量结合看，**Qwen3 1.7B 是这组三款中更值得继续试用的全文翻译候选**：约 175 TPS、短上下文峰值约 1.7 GiB，本轮翻译质量也较好。Qwen2.5 1.5B 有明显事实和操作关系错误，不宜仅为速度替换。

本轮只评全文翻译，不重测 AI 词卡。上次 Qwen3 词卡结构失败仍是未解决问题；当前 3B 词卡也有缺陷。没有一款获得“全部功能可无条件替换”的结论，默认模型未改。

质量门槛实际执行结果：Qwen3 相对当前 3B 的已合格用例**无退步**；但 `--gate` 要求 18/18，全量门槛仍因 T18 不合格而失败。1.5B 相对 3B 在 T01、T05、T14 退步。
