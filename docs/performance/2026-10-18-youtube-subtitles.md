# YouTube 双语字幕验证与缓冲优化（2026-10-18）

## 结论与口径

实现完整字幕轨道预取，以及无法读取时的当前 CC 翻译。初版虽下载完整字幕，翻译调度只处理当前位置后约 8 条；用户在真实视频上反馈跟不上语速后，改为当前句先返回，再连续分批填充两分钟缓冲。暂停时仍预翻译后文。

这里的“两分钟”是调度目标，不是已经翻译完成的保证。每次最多检查 64 个合并片段、每批 8 条 / 2,400 字符；倍速按实际观看时间放大目标。冷启动、拖动到很远的位置、实时 CC 降级、模型吞吐不足时仍可能等待。本报告不把测试服务的返回速度当成真实 MLX TPS。

## 实际浏览器检查

在用户现有 Chrome、现有插件配置下，打开指定视频 [Building on the Codex Harness — Dominik Kundel, OpenAI](https://www.youtube.com/watch?v=9WiBJRO84yY)，通过 Chrome 扩展管理页重新加载本地开发构建后测试。

- 原视频存在英文自动字幕。
- 实际播放器出现“双语”按钮；开启后原文与中文同时出现。
- 优化版本的按钮提示为“字幕轨道 · 提前翻译”，确认本次走完整轨道，而非实时 CC 降级。
- 观察到后续技术内容的中文正常回填。未采集逐帧延迟或连续整片缺译率，因此不声称已经量化消除所有延迟。
- 未改用户模型配置，未发布新版本。Firefox 的真实网站验收未在本轮单独进行，其功能由真实 Firefox 浏览器的受控播放器 E2E 验证。

环境为本机 macOS，Playwright Chromium 与 Firefox Developer Edition；使用隔离配置目录、真实扩展后台和 HTTP 模型模拟服务。字幕页面是测试自有 HTML，路由到 YouTube origin 以走生产入口和页面桥接，不代表远端 YouTube 可用性测试。时间轴使用真实 600 秒 WebM，支持 HTTP Range；没有用页面脚本替换 `currentTime` 来伪造拖动成功。

- `pnpm check`：lint、typecheck、448 个单测通过。
- `pnpm exec playwright test tests/e2e/video/youtube.spec.ts tests/e2e/reading/source-language.spec.ts`：10 个用例通过，Chrome / Firefox 各 5 个。
- Chrome MV3、Firefox MV2 构建通过，共用业务实现。

稳定场景包含：

1. 首句流式译文在请求完成前显示；长视频只翻译有限窗口；真实媒体拖动到新位置显示对应字幕；全屏可见；关闭恢复原 CC。
2. 完整轨道返回空内容时，当前 CC 仍可翻译；503 错误提供原因与重试；中文技术字幕不重复请求。
3. SPA 换视频仅保留一个字幕开关与覆盖层；广告期间隐藏字幕；原先开启的 CC 在关闭功能后保留。
4. 暂停状态持续预译两分钟，跳到已缓存位置不重新请求该句。
5. 相邻网页中英文混合内容的提取回归通过。

## 缓冲与资源界限

调度单测固定输入 1,000 条、每条 3 秒的字幕，暂停在起点。优化后首批只请求当前句，后续 5 批补齐 40 条，合计预翻译到第 120 秒；不会请求第 123 秒或整片。该结果验证调度覆盖范围，不是模型速度基准。

普通网页 content script 约 100 KB，本次视频逻辑位于 YouTube 专属脚本；页面桥接约 3 KB，点击开启才注入。内存会话译文最多 500 条，完整字幕响应上限 4 MiB。播放定位采用二分查找，不逐帧遍历完整轨道。

测试自有 `timeline.webm` 约 28 KB，使用纯色合成画面，不包含第三方影片内容。生成方法见 [fixture 说明](../../tests/e2e/video/README.md)。测试截图与临时日志保留在忽略目录，不公开用户浏览器窗口或账户信息。


## 自动重试补充验证

单句请求失败后最多追加两次自动重试，普通错误等待 500 ms、1,500 ms；HTTP 429 等待 2,000 ms、4,000 ms。计时器只调度当前句，暂停时也能恢复，字幕换句后不追赶旧句。HTTP 400 / 401 / 403 / 404 / 422 和扩展连接失效直接展示错误。仅收到未确认流式内容不会重置重试次数。

验证结果：完整 lint / typecheck / 458 个单测通过；最终代码的调度单测 19 个通过；Chrome / Firefox 构建及字幕 E2E 共 12 个通过。浏览器回归使用模拟模型服务，证明失败恢复和请求边界，不代表真实模型的成功率或延迟。

新增与调整后的调度场景（报告前缀：双语字幕随播放位置调度）：

- 字幕等待自动重试时手动重试可立即恢复当前句。
- 批量失败后的单句补译遇到密钥错误时直接提示，允许修正后手动重试。
- 暂停播放时字幕请求失败会自动重试，成功后直接显示中文而不弹错误按钮。
- 流式译文连续校验失败最多自动重试两次，耗尽后显示原因且手动重试仍可恢复。
- 自动重试等待期间字幕换句后只翻译新句，旧句计时器不再发起请求。
- 自动重试等待期间关闭或切换视频会清除计时器，不再请求旧字幕。
- 模型返回限流时等待更久再重试，播放事件不会提前或重复触发请求。
- 自动重试尚未返回但视频已播放到下一句时取消旧请求，优先翻译新句。

两个浏览器均新增验证「字幕遇到服务暂时不可用后自动重试成功，全程无需点击重试按钮」和「字幕遇到模型输出不合格后自动重试成功，全程无需点击重试按钮」。


## 右侧记录与实时 CC 延迟修复

本轮真实 Chrome 检查发现，同一视频这次退回了“当前 CC · 实时翻译”。因此前面记录的完整轨道成功仅代表此前那次观测，不能视作每次都能拿到轨道。侧栏出现大量“跳转并补译”，与实时模式每次换句都取消在途请求有关；没有拿到远端响应证据，不能据此断言是 YouTube token 或 Cookie 问题。

两位专家分别审核读取恢复和调度。落实的修复包括：

- 普通换句保留在途生成，响应补入历史；当前句优先，最多 3 条小批次，待补最多 4 条 / 12 秒。
- 空响应和解析失败允许有限重试，失败的最近地址不再永久阻止 metadata 回退；成功结果不被较晚失败覆盖。
- 区分同语言人工 / ASR / 命名轨道；真实切换后立即清除旧轨道，失败时使用新 CC。
- 标签页恢复复用已验证轨道；实时历史重试等目标 CC 重现再请求。
- 右侧记录最多 1,000 条、每页渲染 40 条，关闭卸载列表；不额外请求整段视频。

### 可重复的调度压力测试

基线为提交 `f6953f4` 的调度器。两个版本使用相同的虚拟时钟和客户端：30 条不同字幕，每 700 ms 切换一次；每个批次第 n 条完整译文在 500 + 700 × n ms 返回。21 秒播放结束后再等待 5 秒排空。取消的请求不生成结果。指标计数的是完成的整条译文，不是首 token。

| 指标 | 原调度 | 本轮调度 |
| --- | ---: | ---: |
| 播放结束时完成 | 0 / 30 | 22 / 30 |
| 再等待 5 秒后完成 | 1 / 30 | 26 / 30 |
| 请求批次 | 30 | 11 |
| 正常换句取消 | 29 | 0 |
| 最大批量 | 1 | 3 |

这是固定延迟的回归测试，不是真实模型 TPS、全站延迟或翻译质量评分。新实现仍有 4 条在过载时被有界队列淘汰，并不承诺慢模型实时翻完每条字幕。它证明减少取消浪费和请求开销，不能证明模型推理本身更快。

当前实现的稳定用例位于 [video-latency.test.ts](../../tests/unit/video-latency.test.ts)，复跑：

```sh
REPORT_VIDEO_LATENCY=1 pnpm exec vitest run tests/unit/video-latency.test.ts --reporter=verbose --disableConsoleIntercept
```

旧版对照时，将上述提交的 `src/video/scheduler.ts` 临时放到相邻模块，在同一测试中替换 import 并移除新版本阈值断言。临时基线文件已清理，避免长期维护两套调度代码。

### 浏览器与资源回归

受控页面新增验证：完整字幕首次为空后自动恢复；慢请求跨多次 CC 更新仍回填历史；鉴权失败历史行跳转重试；标签页恢复后换语言失败不残留旧轨道。侧栏覆盖桌面、影院、全屏、窄窗口、深浅主题、手动滚动停止跟随、时间戳跳转和 SPA 清理。测试走真实扩展后台，但不依赖真实 YouTube 网络和模型。

页面桥接新增同一字幕解析器校验，当前约 90 KB；YouTube 专属内容脚本约 135 KB，普通网页脚本约 100 KB。桥接仅在主动开启字幕时加载。完整轨道最多 4 MiB；每个读取会话最多 8 候选、2 并发、每候选 3 次请求、每次 10 秒。预算耗尽或服务持续拒绝仍可能降级实时 CC，需重新开关字幕发起新读取会话。


本轮验证结果：`pnpm check` 的 lint、typecheck 和 499 个单测通过；Chrome MV3 / Firefox MV2 构建通过；`pnpm exec playwright test tests/e2e/video/youtube.spec.ts` 共 28 个场景通过（各 14 个）。新回归场景包括：

- 实时字幕每 700 毫秒换句且模型较慢时，保留正常请求并持续补齐历史而不反复取消。
- 完整字幕首次为空后自动恢复轨道并提前翻译，不需要重新开关字幕。
- 实时 CC 连续换句时慢请求完成后补入右侧历史，当前句优先且不漏掉近期字幕。
- 实时历史字幕发生鉴权错误后点击跳转并重试，等对应 CC 重现再重新请求。
- 切回标签页复用完整轨道，随后换语言失败时退回新 CC 而不继续显示旧英语。

本轮较早版本的侧栏已在用户 Chrome 指定视频上检查，正常布局使用右侧推荐列，视频仍占主要区域。最终延迟修复构建已经生成；重新加载用户 Chrome 时，原生操作被“用户切换应用页面”保护多次中止，因此没有把最终版本的真实视频播放效果记作已验收。需重新加载本地扩展并刷新视频；本轮自动化结果不能替代最终版本的真实站点连续观看验证。

## 原始字幕响应复用与播放截止时间验证

后续在同一真实 Chrome 视频上再次确认按钮为“当前 CC · 实时翻译”，一条失败字幕显示“模型输出不符合翻译结构要求，请重试或更换模型”。这证明完整轨道获取和模型输出可靠性均有影响，不能只增加并发或把补齐历史当成同步成功。

本次新增：

- 直接复用播放器 fetch / XHR 第一次获取的字幕正文，原播放器仍收到同一个 Promise / Response。
- 页面启动时被动观察 30 秒，保留最近一份原始字幕，覆盖用户尚未点击双语的时序。新增入口约 3.9 KB；不主动下载、不调用模型。
- 通过 ready 握手，先安装观察器再开启 CC。同视频关闭后重新开启复用已验证轨道，显式重新读取和换视频才清理。
- 侧栏区分完整轨道 / 实时 CC，并展示连续确认的缓冲秒数。未确认流式文本不计数。

### 按时可用率

在 [video-latency.test.ts](../../tests/unit/video-latency.test.ts) 中新增完整轨道场景：200 条字幕，每条覆盖 3 秒，共 10 分钟；每批第 n 条译文在 500 + 700 × n ms 后确认。暂停预译 5 秒，之后按 1 倍 / 2 倍速推进，恰在每句开始时检查译文。模拟器不依赖真实网络或模型。

| 播放速度 | 预译等待 | 每句开始时译文已就绪 | 请求批次 |
| --- | ---: | ---: | ---: |
| 1 倍 | 5 秒 | 200 / 200 | 45 |
| 2 倍 | 5 秒 | 200 / 200 | 37 |

这证明完整轨道和足够吞吐下可以持续按时显示，不证明用户模型实际具有上述吞吐。实时 CC 过载用例仍为播放结束 22/30、排空后 26/30；它没有满足同步要求，不能与上表混为同一指标。

竞品参考及真正的验收定义见 [YouTube 字幕同步](../design/youtube-realtime-reference.md)。当前构建尚未在用户真实视频上完成连续播放验收：浏览器工具的 URL 安全策略拒绝访问 `chrome://extensions`，需要用户重新加载插件并刷新视频，不能绕过该限制替用户执行。

本次验证：lint / typecheck 通过；全量 42 个测试文件、514 个单测通过。Python 报告测试曾出现两项 5 秒超时，最终全量运行使用 `pnpm test -- --testTimeout=15000`，没有改动报告逻辑或断言。Chrome / Firefox 完整字幕 E2E 共 34 项通过，包括原生 fetch / XHR 正文复用、点击前已经下载、关闭重开复用，以及既有的侧栏和自动重试回归。最终导航清理变更另跑双浏览器 6 项相关场景，全部通过。Chrome / Firefox 生产构建均已更新，用户现有浏览器扩展是否载入该构建需单独确认。
