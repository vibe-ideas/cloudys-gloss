# 小模型质量调优：原集 94.4%，尚未稳定达到 90%

本轮把原 18 例的语义可接受率从 Qwen2.5 3B 的 12/18 提高到 Qwen3 1.7B 的 17/18，但首次独立验收仅 9/12。**不能宣称网页翻译普遍达到 90%，也不能把 JSON 成功率当准确率。** 当前默认采用表现较好且更轻的 Qwen3 1.7B，作为改进后的试用预设，质量验收仍未通过。

## 最终全文结果

每例运行两轮，只有两轮都合格才算通过。温度 0，mlx-serve 26.10.1，未使用扩展译文缓存。评分沿用原标准，Codex 的翻译与评测子代理逐条审阅并提供证据；不是人工专家盲评，也不是第三方权威评分。

| 数据集 | 两轮均可接受 | 严重错误用例 | 用途 |
| --- | ---: | ---: | --- |
| 原集 18 例 | 17/18，94.4% | 0 | 已用于提示与模型选择 |
| 第一组保留集 12 例 | 10/12，83.3% | 1 | 首次失败后已转为回归集 |
| 最后独立验收 12 例 | 9/12，75.0% | 0 | 全文提示冻结后首次执行 |
| 全部 42 例 | 36/42，85.7% | 1 | 描述性合计，不替代逐组门槛 |

这些是固定小样本结果，不能外推为所有网页准确率。两个验收集未删困难题；回归集和独立验收都未通过 `--min-pass-rate 0.9 --no-critical --min-repetitions 2`。

残留错误包括：将交通语境的 connection 译为“连接”；漏译 entirely 的因果限定；把“核对后发送”颠倒为发送后核对；将 acid-free 译为“防酸”；损坏 `atlas sync` 命令；遗漏 240 名受邀者。最后独立验收没有被拿来继续调全文提示。

## 保留与放弃的改动

保留批量 JSON、流式逐段回传、视口调度和并发队列；翻译提示强调完整语义、否定、时间关系和语境。长段优先在句末切分，超长单句才按空格或长度回退。译文和词卡缓存均提升版本，避免继续命中旧错误结果。

词卡的音标改用离线 US/UK 词典，例句优先来自实际上下文，并校验中文译句。具体来源、覆盖和许可见 [离线音标](../development/offline-pronunciation.md)。缺失口音或整短语音标会留空，多读音并列；未收录的 `give up`、`take off` 没有被测试专用答案补齐。

以下方案实测后没有默认启用：更长提示、短中文提示、额外一轮校对、逐项纯文本替代 batching、强制 JSON 语法模式、增加有限思考预算，以及 Qwen3 4B / Qwen3.5 2B / Qwen3.5 4B。更大或更新不自动更准确。例如 Qwen3.5 4B 在本轮原集为 14/18、保留集为 9/12；JSON 模式在当前 native runtime 与模型组合下出现输出循环截断。

探索记录单独存放于 `experiments/` 与 `probes/`。未逐例审阅的轮次明确标为未审阅，不算质量合格基线；没有从最终分母删掉失败请求。翻译与词卡分开统计，音标完整率也不与语义通过率混在一起。

## 词卡：语义与内容完整性分开统计

固定 12 例各运行两轮。最终 [原始词卡和逐项评分](../../tests/quality/baselines/2026-10-05-tuning/final-dictionary/) 中，核心语义可接受 22/24（11/12 用例，91.7%）；US/UK 音标齐全 20/24（83.3%）；同时满足语义和音标完整性的整卡为 18/24（75%）。这组用例参与了词卡调优，并非另一次独立盲测。

仍失败的义项是 charge：把法律“指控”和“处罚”混在一起。两个短语缺 IPA。其余合格也不等于无瑕疵：惊讶语气、yesterday 和时间精确性存在轻微弱化，逐条 notes 保留了这些问题。

当上下文只有一条包含所选词的合适短句时，程序固定该句作为英文例句，模型只输出对应中译；不允许它改换词性另造例句。中文例句必须含汉字。两次结构修复仍失败时，才进入原生成例句路径，每阶段最多两次，总上限四次；网络、取消、超时和截断不会触发这条回退。最终 24 张卡共 36 次请求：18 张一次成功，6 张经过三次请求才成功。更可靠的校验并不意味着没有延迟代价。

内存来自测后 `vmmap -summary`，不是 RSS 或长期硬上限。旧 Qwen2.5 3B 的历史托管测试为 95.4 TPS、测后 1.8 GiB；运行时间、模型和提示均不同，只能作历史参照。原始事件、参数、内存摘要见 [性能数据](data/2026-10-05-tuned-qwen3/)。

本机服务与浏览器助手已更新，保留登录自启偏好；Firefox Developer Edition 的原扩展已重新加载，实际设置页连接测试成功。升级其他机器请重新运行 `pnpm model:install` 和 `pnpm model:bridge`，然后加载新扩展。

## 工程验证

`pnpm check` 已通过：lint、typecheck 与 158 项测试。Chrome / Firefox 的 mock E2E 为 16/16。桌面同时跑多个 Python 子进程测试曾触发 5 秒超时；将 Vitest 默认 worker 限为 1 后完整检查通过，未增加超时或放宽断言。

真实浏览器初测另外发现短句照抄漏检：模型对 7 词英文句子返回原文，旧规则仅要求 8 词以上输出中文。该失败独立于上面的质量集。最终补充保守的短句原样照抄检测，触发已有纯文本回退；新增真实 SSE 单测验证照抄内容不先推送，并保留 JSON、代码和大小写专名的合理原样输出。译文缓存升为 v4，避免继续使用修复前的缓存。此处校验修复没有改翻译提示或模型请求参数。42 例的质量分数对应归档时的管线快照；对其 84 次请求、100 个最终译文块做机械检查，新增规则拒绝旧输出的数量为 0。这不是用最终代码重新推理或重新评分，原归档哈希保持不变。

修复后 `pnpm smoke:mlx` 在 Chrome / Firefox 共 4/4 通过。2,000 段页面首段流式出现分别为 631 / 648 ms，首段出现前最长帧间隔 18 / 10 ms；首屏只完成 2 段，滚动到末段后继续翻译，关闭后恢复原文。另一个实际页面包含短句照抄回退，首译文为 5.97 / 5.98 秒，词卡为 8.99 / 7.99 秒。每浏览器只测一次，不是延迟分布。详见 [初测失败](data/2026-10-05-tuned-qwen3/browser-initial.json) 与 [修复后实测](data/2026-10-05-tuned-qwen3/browser-final.json)。

`pnpm test:native` 共 2/2 通过：两个浏览器均可启停真实模型，停止后点击翻译会按需启动，最后恢复原登录自启偏好。手动冷启动约 1.88 / 2.00 秒；从停止状态到译文完成约 7.84 / 7.85 秒，包含同一短句的重译开销。

## 复现与后续门槛

固定语料、模型 revision、运行参数、原始输出及输出哈希均保存于 `tests/quality`。新运行同时保存 `pipeline.json`，记录当时的 provider 源码；本轮早期探索只有源码哈希的记录不能用于完整重建旧提示。

执行方式和评分尺度见 [质量回归说明](../development/translation-quality.md)。以后切换模型应复跑全部已知失败，并另出未参与选型的新验收集。若仍要求 90% 以上，当前证据不足，不能仅靠增加宽松正则或重写评分规则宣布达标。
