# 请求调度与等待体验优化：实测和交叉审核

本轮保留了后台三级队列、跨请求共享翻译、隐藏标签页暂停新增工作、网页失败条目局部重译，以及词卡离线音标先显示。未更换模型或提高本地并发。

词卡“只修复例句中文”的候选在真实质量审查中发现字段退步，已撤回。其速度结果不计入最终收益。

## 已采用的改动

- **主动操作优先：** 网页/PDF 手动重翻、查词先于待执行的可见内容和预取；同优先级 FIFO，每八次优先插队后服务最老任务。已经执行的推理不被频繁抢占。
- **同文共享：** 不同批次、不同页面的同一缓存键复用进行中的翻译；一个页面取消不影响其他订阅者，全部取消才中止上游。显式重翻单独启动并接管后续普通请求，旧请求不能覆盖更新的缓存。
- **执行前复查缓存：** 避免任务排队期间其他请求已经完成，而本任务仍按旧的 cache miss 继续推理。
- **隐藏页暂停：** 暂停新增翻译和扫描，切回增量恢复。已提交的至多两批不因单纯切页被强行中断；长段手动重翻保存已经完成的片段。
- **网页局部重译：** 完整 JSON、条目数量及映射可信时，保留合法条目，仅补译失败项；破损 JSON 或数量错误仍按原策略恢复。所有修复最终成功后才确认并缓存。
- **词卡先可用：** 点击小组件后独立读取离线 IPA，不等待模型队列、不唤醒模型；加载/错误时仍可使用发音按钮。完整词卡稍后补齐，关闭和换词隔离迟到结果；补内容时锁定展开侧，窗口 resize 时重新定位。

上述行为保留原本的 header、面包屑等组件覆盖、语义分块、SPA 增量处理及用户主动点击划词入口。

## 真实 MLX 对照

M4 Pro，本机 `mlx-serve 26.10.1`，`Qwen/Qwen3-1.7B-MLX-4bit`，Temperature 0、Concurrency 1。相同合成公开文本、相同接口，按 **旧 → 新 → 新 → 旧** 顺序运行，每个版本每个场景两次。

| 场景 | 旧版中位数 | 新版中位数 | 结论 |
| --- | --- | --- | --- |
| 两页同时翻译相同两段，等待两页全部完成 | 2591 ms，2 次请求 | 1293 ms，1 次请求 | 此重复内容场景约减少 50% 等待和一半推理请求 |
| 已有任务和预取排队时主动重翻，等待该操作完成 | 2566 ms | 1513 ms | 此混合场景主动操作约减少 41% 等待 |
| 上述混合场景所有任务全部完成 | 2611 ms | 2624 ms | 总工作量未减少；优先级改善用户当前操作，没有提高模型吞吐 |

这是 **background service 层** 的真实模型测量，IndexedDB 使用测试内存实现，每个场景清空结果缓存；服务 prompt cache 保持其现有设置。它不包含浏览器绘制，不能外推为任意网页快一倍。两次重复不足以估计 P95，桌面负载也会造成波动。

数据：[ABBA 原始记录](data/2026-10-06-service-abba/results.jsonl)、[摘要](data/2026-10-06-service-abba/summary.json)、[元数据](data/2026-10-06-service-abba/metadata.json)、[源码快照](data/2026-10-06-service-abba/pipelines.json)。该测量只执行网页翻译；快照中试验期词卡修复后来被撤回，不影响此场景调用的翻译路径。

## 被拒绝的词卡试验

请求级诊断确认 `cloudy` / `light` 首轮和整卡重试的错误都在 `examples.0.zh`，备用整卡生成分别报告约 654 / 596 个 completion token。随后试验仅翻译固定例句中文、保留首次卡片的其它字段：`light` 约降至 1 秒，`cloudy` 仍约 5.8 秒。

但两轮 12 例的专家审查发现 D08 法律语境的 `charge`：旧版的释义已经混入错误含义，但语境解释仍为“指控”；候选把首次生成的“追究刑事责任”保留下来，使语境解释进一步退步。**总体 22/24 核心语义通过率没变，掩盖了字段质量下降。** 因此没有采用该候选，也没有针对 `charge` 硬编码例外。

生产词卡生成策略恢复为基线，仅增加可选、不含文本或密钥的诊断事件。音标先显示这项交互优化独立保留，不改变 AI 词义。

## 多轮交叉审查

1. **第一轮：** provider 作者审查共享任务实现；调度作者审查网页局部重译。发现缓存进度回调同步抛错时可能遗留任务与未处理 Promise，已修复并补回归。
2. **第二轮：** 调度作者独立审查共享任务；UX 实现者审查隐藏恢复与队列。发现“重翻先开始、普通请求后到”可能夺走缓存写入归属，已改为普通请求共享最新重翻，并补回归。另修复 E2E 固定假设恰好两次请求的问题。
3. **第三轮：** 独立审查词卡分阶段渲染、取消、播放中补卡、边缘定位，以及词卡候选请求预算；词典专家逐例审核真实输出，拒绝存在语义退步的候选。补充播放未结束时补卡不重启语音、完整卡 resize 恢复高度的回归。

专家代码审查没有代替浏览器测试。隐藏标签页测试必须验证真实 `document.visibilityState`；Playwright 的默认聚焦模拟会影响结果，因此该场景使用独立测试窗口与真实 tabs API，并移除测试工具的强制聚焦配置，禁止伪造页面可见性。

最终验证：`pnpm update:firefox --no-open` 完成 lint、typecheck、329 项单测及 Firefox 生产打包；Chrome 生产构建成功。网页/词卡/调度/性能相关 Chrome + Firefox E2E 30/30，PDF 重试 E2E 8/8，真实 MLX 浏览器用例 4/4。最终报告另由评估专家独立核对原始数据、摘要及质量审阅哈希，未发现数字错误。代表性新增场景包括：

- 并发 1 / 2 时两个页面的重叠段落只推理一次，各自返回原顺序结果。
- 共享段落时一个页面关闭不会取消另一页，全部关闭才中止模型且再次进入可重新请求。
- 显式重翻不共享旧请求，旧请求晚返回也不会覆盖新译文缓存。
- 两千段长网页切出标签后暂停新增翻译，切回续译且保留已完成段落。
- 网页翻译占用模型时，点击划词按钮先出现离线音标，模型空闲后原位置补齐释义。

本地 Firefox 更新包为 `.output/local-install/cloudys-gloss-0.1.0-firefox-unsigned.xpi`，本轮只生成包，没有自动覆盖日常浏览器中的已安装版本。CI 的有窗口可见性测试改在 `xvfb-run` 中执行；本轮未运行远端 GitHub CI。

## 保留的边界

- 优先级在提交时确定；另一订阅者加入共享任务时可提级。尚未实现“原预取段滚入可见区后自动更新已提交任务优先级”。
- 当前批次其余项修复最终失败时，合法条目仍是临时结果，页面按原契约撤回；没有引入部分成功正式确认协议。
- 最终 AI 词卡仍可能经历数秒备用生成；先显示音标改善首个可用内容时间，不代表完整卡片已经加速。
- 现有模型仍有词义和 IPA 覆盖问题，本轮不宣称质量达到 100%。

## 复现

`tests/performance/benchmark-service-latency.ts` 需要冻结的旧 `src` 文件目录。可将 `pipelines.json` 的 `before` 对象各项写为对应 `.ts` 文件，再运行：

```bash
BASELINE_DIR=artifacts/performance/optimization-baseline-src \
BENCH_OUTPUT=artifacts/performance/new-service-comparison \
pnpm dlx tsx@4.23.15 tests/performance/benchmark-service-latency.ts
```

输出目录必须不存在。普通性能脚本仍为 `tests/performance/benchmark-services.ts`，质量用例仍在 `tests/quality`，浏览器场景在 `tests/e2e` 与 `tests/live`。
